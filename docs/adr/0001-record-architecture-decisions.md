# ADR-0001: Record architecture decisions; documentation as code

- **Status:** Accepted
- **Date:** 2026-10-24

## Context

Three people work on backend, frontend and DevOps in parallel. Misunderstandings about field names, types and rules are the main integration risk. Decisions made in chat are forgotten.

## Decision

- Documentation lives in the repository under `/docs` as Markdown with Mermaid diagrams, and changes through Pull Requests like code.
- Data definitions have one source ([03](../03-domain-model.md)), the API contract has one source ([05](../05-api-contract.md)).
- Significant decisions are recorded as ADRs in `/docs/adr`.
- A PDF version is generated by CI for submission.

## Alternatives considered

| Option | Pros | Cons |
|---|---|---|
| Google Docs / Word | Familiar, easy comments | Not versioned with code, drifts out of date, no review |
| Confluence / Notion | Nice editing | Separate tool, not linked to PRs |

## Consequences

Docs and code are reviewed together; history shows who changed what. Writers must know basic Markdown.
