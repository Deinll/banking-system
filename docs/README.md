## 3. Documentation rules

1. **One fact — one place.** Field definitions live only in [03](03-domain-model.md); endpoints and DTOs only in [05](05-api-contract.md). Other documents link, they do not copy.
2. **Everything has an ID** so it can be referenced from issues, PRs, commits and tests:

   | Prefix | Meaning | Defined in |
   |---|---|---|
   | `FR-xxx-nn` | Functional requirement | 02 |
   | `NFR-xxx-nn` | Non-functional requirement | 02 |
   | `BR-nn` | Business rule | 02 |
   | `US-nn` | User story | 02 |
   | `TC-nn` | Test case | 09 |
   | `ADR-nnnn` | Architecture decision | adr/ |
   | `PKG-nn` | Extension package (post-MVP feature set) | 12 |

3. **Docs change through Pull Requests**, exactly like code. Changes to [03](03-domain-model.md) or [05](05-api-contract.md) require approval from **both** the backend and the frontend developer.
4. **IDs are never reused.** A removed requirement is marked ~~struck through~~ with a note, not deleted.
5. Diagrams are written in **Mermaid** (rendered natively by GitHub).
6. Language: **English**. Code, identifiers, commits and docs are in English.
7. Markers used in tables: **MVP** = part of the core scope; **PKG-nn** = planned in an extension package; **Reserved** = value defined now so it can be used later without breaking changes.

## 4. Glossary

Polish banking terms are given in brackets because the bank simulates the Polish market.

| Term | Meaning |
|---|---|
| **User** | Login identity (email + password + role). Every person who can sign in has one. |
| **Customer** (*klient*) | A person who is a client of the bank: personal data, customer number. Admins are users but **not** customers. |
| **Customer number** (*numer klienta*) | 8-digit public identifier of a customer, generated by the bank. |
| **Account** (*rachunek bankowy*) | A bank account holding money. Not to be confused with the user's login. One customer may have several accounts. |
| **Account product** (*produkt*) | Template defining the rules of an account type (interest, limits, allowed operations). Every customer account is an instance of a product. |
| **Personal account** (*konto osobiste, ROR*) | Everyday account: transfers to anyone, ATM operations. |
| **Savings account** (*konto oszczędnościowe*) | Interest-bearing account; outgoing transfers only to the customer's own accounts. |
| **System account** | Internal account of the bank itself (e.g. cash desk). Used so that every operation moves money between two accounts. |
| **IBAN / NRB** | International / Polish account number. Polish IBAN = `PL` + 2 check digits + 8-digit bank sort code + 16-digit account number. |
| **Sort code** (*numer rozliczeniowy*) | 8-digit bank + branch identifier inside the IBAN. Trio Bank uses the fictional `99900012`. |
| **Transaction** | One business operation (transfer, deposit, withdrawal, interest…). |
| **Ledger entry** | One side of a transaction on one account: a **debit** (money out) or a **credit** (money in). Each transaction has exactly two entries. |
| **Debit / Credit** (*obciążenie / uznanie*) | From the account's perspective: debit decreases, credit increases the balance. |
| **Double-entry bookkeeping** | Every transaction debits one account and credits another for the same amount, so the sum of all balances is always 0. |
| **Title** (*tytuł przelewu*) | Free-text description of a transfer, max 140 characters. |
| **Idempotency key** | Unique key sent by the client with a money operation, so that repeating the same request never executes it twice. |
| **Interest accrual / capitalization** (*naliczanie / kapitalizacja odsetek*) | Interest is calculated daily (accrued) and paid to the account monthly (capitalized). |
| **Belka tax** (*podatek Belki*) | 19% tax withheld from interest in Poland (simulated). |
| **Elixir** | Polish interbank clearing system processing transfers in sessions (simulated in PKG-08). |
| **BLIK** | Polish mobile payment system (simulated in PKG-10/11). |
| **PESEL** | Polish 11-digit national identification number; encodes the date of birth and has a check digit. |
| **ATM channel** | Simulated cash machine operated by the customer in the web app. |
| **Branch channel** | Cash operations performed by an admin acting as a bank teller. |
